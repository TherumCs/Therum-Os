## Findings

### F1 · Security · CRITICAL · **Resolved** (deployed + verified on production)
**Any cookie named `th_session` counted as a signed-in admin.**

`hasAdminSession()` in `src/api/routes/wooCompat.ts` tested only that the name
appeared in the Cookie header — never the signature, the expiry, or the role.
Confirmed against production:

```
curl -H "Cookie: th_session=garbage-not-a-jwt" \
  "https://sidemoney.co/wc-auth/v1/authorize?...&scope=read_write" → >Approve<
```

**Why it matters:** the POST behind that screen issues a `read_write` store
credential and delivers it to a `callback_url` the caller supplies. So the
header above turns the endpoint back into a credential vending machine — the
same class as the hole closed in `93dcf6f`, through a different door. Standard
violated: `standards.md` → Backend/Node, and OWASP A07 (identification and
authentication failures).

**Fix (written, builds, tested):** verify the JWT with the running secret, and
reject any role that is not `admin`/`custom` — the 2FA challenge token is signed
with the same secret and must not stand in for a session.

**Deployed and verified on production 2026-08-02.** Same three probes:
forged cookie → sign-in form · no cookie → sign-in form · real signed token →
Approve. And the POST, which is what actually mints: `approve=1` with
`th_session=garbage-not-a-jwt` returned the sign-in form and the credential list
was unchanged either side of it (`Printful connection`, `Tapstitch connection`).

### F2 · Test maturity · HIGH · **Resolved**
**The suite's admin fixture was a fake string, so it could never have caught F1.**

`asAdmin` was the literal `th_session=admin-session-for-tests`, and its comment
documented the hole as intent: *"The value only has to LOOK like a session
cookie."* Every wc-auth test passed for exactly the reason an attacker's forged
cookie passed.

**Why it matters:** a test whose credential is fake proves only that the code
accepts fakes. This is the more important half of F1 — the bug was reachable
because the test agreed with it.

**Fixed:** `asAdmin` now mints a real HS256 token signed with `JWT_SECRET`, and a
new assertion proves `th_session=garbage-not-a-jwt` is refused. Suite 437/437.

### F3 · Correctness · LOW · **Resolved** (deployed)
**`return_url` is never validated — a bad one is a 500.**

`validAuthRequest()` validates `callback_url` (URL-parses it, requires HTTPS off
localhost) but only checks `return_url` is non-empty. `new URL(q.return_url!)`
then throws. Confirmed live: `return_url=not-a-url` → GET 200, **POST 500**.

**Why it matters:** a partner sending a relative or malformed return_url gets an
unexplained 500 instead of the message that names the problem — the same
debugging dead end that cost this week on the Printful and PODpartner
connections. Not exploitable: `sendApprovalScreen()` derives CSP origins through
`new URL().origin` inside a try/catch, so a malformed value is skipped, and
`.origin` cannot emit a space or semicolon to inject a directive.

**Fixed and deployed.** Both URLs now go through one loop that parses each and
requires HTTPS off localhost. Live check: `return_url=not-a-url` →
**400 `{"message":"return_url is not a valid URL."}`**, was a bare 500.

### F4 · Security · LOW · **Resolved** (deployed)
**Maintenance/coming-soon gate uses the same presence-only cookie test.**

`src/server.ts:337` — `/(?:^|;\s*)th_session=/.test(...)`. Anyone can bypass the
coming-soon page by setting any value.

**Why it matters:** low, and the code says so in a comment ("a visibility gate,
not an authorisation boundary") — real admin auth still guards `/tos-admin`. But
the site is pre-launch, so that page is the only thing holding back an unfinished
store from anyone who guesses. Worth closing when F1 ships, since the verified
helper will already exist.

**Fixed and deployed.** Rather than write a third copy of the verify logic, all
three call sites now use one helper — `src/lib/adminSession.ts`. That file is the
single definition of "is an admin signed in", so a fourth caller cannot pick the
weak reading. `test/site.test.mjs` gained a negative case asserting
`th_session=whatever` still gets a 503.

### F5 · Dependencies · LOW · **Resolved** (deployed)
`npm audit --omit=dev` → **2 moderate**, both from `uuid <11.1.1` reached through

before shipping (it uses CJS `require('uuid')`, so this was a real risk): wrote
and re-read an xlsx round-trip, 6420 bytes, values intact.
