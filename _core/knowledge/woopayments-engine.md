Bam's payout speed (instant deposits) lived in **WooPayments**, not raw Stripe. WooPayments only processes for a WordPress/WooCommerce site connected to WordPress.com — the new Fastify stack can't attach to it. Solution built 2026-08-16: a **headless WooPayments engine**, invisible, under sidemoney.co. Bam's hard rules: no `pay.sidemoney.co`, no visible WordPress, everything reached from the TOS admin.

**Where it lives (VPS 2.25.93.243, root@ via therum@):**
- `/var/www/pay` — bare WP (WooCommerce + woocommerce-payments 11.0.0), MariaDB db `paysidemoney` (user `paysm`), PHP 8.3-FPM. Blank `sm-engine` theme (no pages/posts, front-end redirects home). Login moved to `/console` (wps-hide-login). Admin user `sidemoney`.
- nginx vhost `sm-engine-internal` → `listen 127.0.0.1:8088; server_name sidemoney.co;` INTERNAL ONLY. `pay.sidemoney.co` vhost/symlink is REMOVED — do not recreate.
- Main `sites-enabled/sidemoney` vhost proxies only these paths to `upstream therum_pay (127.0.0.1:8088)`: `^~ /wp-json/wc/v3/payments`, `^~ /wp-json/jetpack`, `^~ /wp-content/plugins/woocommerce`. Everything else stays on Fastify (`therum_api`). The vendor bridge `/wp-json/wc/v3/*` (non-payments) and `/wp-content/uploads` + `/wp-includes` (static, `/var/www/sidemoney-static`, snippet `wp-assets.conf`) are UNTOUCHED — never broadly route `/wp-content` or `/wp-json` to the engine or you break the storefront/vendor bridge.

**How the account got reconnected (self-serve, no support ticket):** transplanted the OLD site's Jetpack identity from :10025's DB into the engine — `jetpack_options` (site id **163672804**) + `jetpack_private_options` (blog_token) written RAW via `$wpdb` (wp-cli `option update` double-serializes — must write the serialized string directly). Then set engine `home`+`siteurl` = `https://sidemoney.co` (matches the token → clears Jetpack Safe Mode / `jetpack_url_mismatch` IDC with no wpcom round-trip). WooPayments then authenticated as the real merchant **acct_1J7Rdz2Eh5Vv1oa1** (status complete, deposits daily/T+2). WordPress.com owner = **bam@sidemoney.co** (username TheSidemoneyCompany). Keep :10025 SHUT DOWN — it shares the same token and will fight for the connection.

**Bridge → TOS:** `src/counter/woopayBridge.ts` reads the engine over Basic auth. `.env`: `WOOPAY_BRIDGE_URL=https://sidemoney.co/wp-json`, `WOOPAY_BRIDGE_AUTH=sidemoney:<application-password>`. Two gotchas that 401'd until fixed: engine needs pretty permalinks (`/%postname%/` + flush) for `/wp-json` REST, `fastcgi_param HTTP_AUTHORIZATION $http_authorization` in the engine vhost, and wp-config `$_SERVER['HTTPS']='on'` from `HTTP_X_FORWARDED_PROTO` (app passwords are refused over non-SSL, and the engine sees plain http behind the proxy). Surfaced at route `/counter/payments/woopay` + `admin/app/(app)/payments/WoopaySection.tsx` (data-only, no external links, per Bam).

**Two payout rails (verified on the account):** WooPayments = card / Apple Pay / Google Pay / Link / Klarna / Affirm / Afterpay (all `active`). PayPal balance = PayPal / Venmo / Credit (separate rail, already instant). Cash App = `unrequested` on WooPayments.
